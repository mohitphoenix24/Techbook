1D DPs are the bread and butter of interview DP. They all follow one pattern: **`dp[i]` is the answer for the first `i` elements (or for amount `i`), and it's built from a few smaller indexes.**

:::pattern
- **Take or skip** element i: `dp[i] = max(dp[i−1], dp[i−2] + a[i])` (House Robber).
- **The last step was one of k choices**: `dp[x] = min/sum over choices c of dp[x − c]` (coins, stairs, squares).
- **The last piece was a valid word or code**: `dp[i] = OR/sum over j of (dp[j] && valid(j..i))` (Word Break, Decode Ways).
:::

## Problems

:::problem House Robber {level=medium lc=house-robber tags="dynamic programming,take or skip"}
Houses in a row hold `nums[i]` money. You can't rob two **adjacent** houses. Maximize the total.

Example: `[2,7,9,3,1]` → `12` (2 + 9 + 1).

:::hint Hint
For house i, either skip it (the best stays `dp[i−1]`) or rob it (then house i−1 must be skipped: `dp[i−2] + nums[i]`).
:::

:::solution
**State:** `dp[i]` = the best total using houses `0..i`. **Transition:** `dp[i] = max(dp[i−1], dp[i−2] + nums[i])`. Only two previous values are needed.

```cpp run
#include <bits/stdc++.h>
using namespace std;

int rob(const vector<int>& a) {
    int prev2 = 0, prev1 = 0;                       // dp[i-2], dp[i-1]
    for (int x : a) {
        int cur = max(prev1, prev2 + x);            // skip house i, or rob it
        prev2 = prev1; prev1 = cur;
    }
    return prev1;
}

int main() { cout << rob({1, 2, 3, 1}) << ' ' << rob({2, 7, 9, 3, 1}) << ' ' << rob({2, 1, 1, 2}) << '\n'; }
```

:::complexity
Time | O(n) |
Space | O(1) |
:::

`[2,1,1,2]` → 4 shows why "take every other house" is wrong. Sometimes you skip **two** houses in a row.
:::
:::

:::problem House Robber II {level=medium lc=house-robber-ii tags="dynamic programming,circular"}
Same, but the houses are in a **circle**: the first and last are neighbours.

:::hint Hint
The first and last houses can't both be robbed. So the answer is max(rob houses `0..n−2`, rob houses `1..n−1`). Two runs of the linear version.
:::

:::solution
```cpp run
#include <bits/stdc++.h>
using namespace std;

int robRange(const vector<int>& a, int lo, int hi) {
    int p2 = 0, p1 = 0;
    for (int i = lo; i <= hi; i++) { int c = max(p1, p2 + a[i]); p2 = p1; p1 = c; }
    return p1;
}
int rob(const vector<int>& a) {
    int n = a.size();
    if (n == 1) return a[0];
    return max(robRange(a, 0, n - 2), robRange(a, 1, n - 1));   // exclude the last, or exclude the first
}

int main() { cout << rob({2, 3, 2}) << ' ' << rob({1, 2, 3, 1}) << ' ' << rob({1, 2, 3}) << '\n'; }
```

:::complexity
Time | O(n) |
Space | O(1) |
:::

"Break the circle by fixing one decision" is a reusable trick for circular problems.
:::
:::

:::problem Decode Ways {level=medium lc=decode-ways tags="dynamic programming,counting,strings"}
Letters are encoded as `A=1 … Z=26`. Count the ways to decode a digit string.

Example: `"226"` → `3` (`2 2 6`, `22 6`, `2 26`); `"06"` → `0`.

:::hint Hint
`dp[i]` = the number of ways to decode the first i characters. The last piece is either one digit (valid if it isn't '0') or two digits (valid if between 10 and 26).
:::

:::solution
```cpp run
#include <bits/stdc++.h>
using namespace std;

int numDecodings(const string& s) {
    int n = s.size();
    vector<int> dp(n + 1, 0);
    dp[0] = 1;                                                    // the empty prefix: 1 way
    for (int i = 1; i <= n; i++) {
        if (s[i - 1] != '0') dp[i] += dp[i - 1];                  // last piece = 1 digit
        if (i >= 2) {
            int two = (s[i - 2] - '0') * 10 + (s[i - 1] - '0');
            if (two >= 10 && two <= 26) dp[i] += dp[i - 2];       // last piece = 2 digits
        }
    }
    return dp[n];
}

int main() { for (string s : {"12", "226", "06", "11106", "10", "2101"}) cout << s << "->" << numDecodings(s) << ' '; cout << '\n'; }
```

:::complexity
Time | O(n) |
Space | O(n) | O(1) by keeping only two values
:::

Zeros are the trap: `'0'` can't stand alone, and `"06"` isn't a valid two-digit code. The `two >= 10` check handles that.
:::
:::

:::problem Coin Change {level=medium lc=coin-change tags="dynamic programming,unbounded knapsack"}
Return the **fewest** coins that add up to `amount` (each coin can be used unlimited times), or −1.

Example: `coins=[1,2,5], amount=11` → `3` (5+5+1).

:::hint Hint 1
Greedy (always the largest coin) fails: coins `[1,3,4]`, amount 6. Greedy gives 4+1+1 = 3 coins, but 3+3 = 2.
:::

:::hint Hint 2
`dp[x]` = the fewest coins to make x. Try every coin as the **last** one: `dp[x] = 1 + min(dp[x − c])`.
:::

:::solution
```viz algo=coin-change
```

```cpp run
#include <bits/stdc++.h>
using namespace std;

int coinChange(const vector<int>& coins, int amount) {
    const int INF = 1e9;
    vector<int> dp(amount + 1, INF);
    dp[0] = 0;
    for (int x = 1; x <= amount; x++)
        for (int c : coins)
            if (c <= x && dp[x - c] != INF) dp[x] = min(dp[x], dp[x - c] + 1);
    return dp[amount] == INF ? -1 : dp[amount];
}

int main() { cout << coinChange({1, 2, 5}, 11) << ' ' << coinChange({2}, 3) << ' ' << coinChange({1, 3, 4}, 6) << ' ' << coinChange({1}, 0) << '\n'; }
```

:::complexity
Time | O(\text{amount} \times \text{coins}) |
Space | O(\text{amount}) |
:::
:::
:::

:::problem Coin Change II {level=medium lc=coin-change-ii tags="dynamic programming,counting,loop order"}
Count the **combinations** of coins that make up `amount` (order doesn't matter: 1+2 and 2+1 are the same).

Example: `amount=5, coins=[1,2,5]` → `4`.

:::hint Hint 1
`dp[x] += dp[x − c]`. But which loop goes outside, coins or amounts?
:::

:::hint Hint 2
With **coins outside**, each combination is built in one fixed order of coin types, so it's counted once. With **amounts outside**, every ordering is counted: those are permutations.
:::

:::solution
```cpp run
#include <bits/stdc++.h>
using namespace std;

long long combinations(const vector<int>& coins, int amount) {   // order doesn't matter
    vector<long long> dp(amount + 1, 0);
    dp[0] = 1;
    for (int c : coins)                       // coins OUTSIDE
        for (int x = c; x <= amount; x++) dp[x] += dp[x - c];
    return dp[amount];
}

long long permutations(const vector<int>& coins, int amount) {   // order matters ("Combination Sum IV")
    vector<long long> dp(amount + 1, 0);
    dp[0] = 1;
    for (int x = 1; x <= amount; x++)         // amounts OUTSIDE
        for (int c : coins) if (c <= x) dp[x] += dp[x - c];
    return dp[amount];
}

int main() {
    cout << "combinations: " << combinations({1, 2, 5}, 5) << ", ordered sequences: " << permutations({1, 2, 5}, 5) << '\n';
    cout << "combinations of [1,2,3] for 4: " << combinations({1, 2, 3}, 4) << " vs ordered: " << permutations({1, 2, 3}, 4) << '\n';
}
```

:::proof Why coins-outside counts each combination exactly once
After processing coin types $c_1, \ldots, c_j$, `dp[x]` counts the multisets of those types that sum to $x$. Adding type $c_{j+1}$: the inner loop goes **upward** in $x$, so `dp[x − c]` already includes multisets that use $c_{j+1}$ any number of times. Each multiset is built once, by deciding how many copies of each type to use, **in the fixed order of types**. With amounts outside, the last coin can be **any** type at every step, so 1+2 and 2+1 are counted separately.
:::

:::complexity
Time | O(\text{amount} \times \text{coins}) |
Space | O(\text{amount}) |
:::
:::
:::

:::problem Word Break {level=medium lc=word-break tags="dynamic programming,strings,hash set"}
Can `s` be split into a sequence of dictionary words (each can be reused)?

Example: `"leetcode", ["leet","code"]` → `true`; `"catsandog", ["cats","dog","sand","and","cat"]` → `false`.

:::hint Hint
`dp[i]` = whether `s[0..i)` can be split. `dp[i]` is true if, for some j, `dp[j]` is true and `s[j..i)` is a word. Only try `j` within the maximum word length of `i`.
:::

:::solution
```cpp run
#include <bits/stdc++.h>
using namespace std;

bool wordBreak(const string& s, const vector<string>& dict) {
    unordered_set<string> words(dict.begin(), dict.end());
    size_t maxLen = 0;
    for (auto& w : dict) maxLen = max(maxLen, w.size());
    int n = s.size();
    vector<bool> dp(n + 1, false);
    dp[0] = true;
    for (int i = 1; i <= n; i++)
        for (int j = max(0, i - (int)maxLen); j < i && !dp[i]; j++)
            if (dp[j] && words.count(s.substr(j, i - j))) dp[i] = true;   // last word = s[j..i)
    return dp[n];
}

int main() {
    cout << boolalpha << wordBreak("leetcode", {"leet", "code"}) << ' ' << wordBreak("applepenapple", {"apple", "pen"}) << ' '
         << wordBreak("catsandog", {"cats", "dog", "sand", "and", "cat"}) << '\n';
}
```

:::complexity
Time | O(n \cdot L \cdot L) | n positions × L lengths × O(L) substring hashing
Space | O(n) |
:::
:::
:::

:::problem Perfect Squares {level=medium lc=perfect-squares tags="dynamic programming,math"}
Return the fewest perfect squares (1, 4, 9, …) that sum to `n`.

Example: `12` → `3` (4+4+4); `13` → `2` (4+9).

:::hint Hint
It's Coin Change where the coins are the squares up to n: `dp[x] = 1 + min(dp[x − k²])`.
:::

:::solution
```cpp run
#include <bits/stdc++.h>
using namespace std;

int numSquares(int n) {
    vector<int> dp(n + 1, INT_MAX);
    dp[0] = 0;
    for (int x = 1; x <= n; x++)
        for (int k = 1; k * k <= x; k++) dp[x] = min(dp[x], dp[x - k * k] + 1);
    return dp[n];
}

int main() { for (int n : {12, 13, 1, 7, 100}) cout << numSquares(n) << ' '; cout << '\n'; }
```

:::complexity
Time | O(n\sqrt n) |
Space | O(n) |
:::

The math shortcut: by **Lagrange's four-square theorem**, the answer is always ≤ 4, and Legendre's three-square theorem tells you exactly when it's 4 (when $n = 4^a(8b+7)$). That gives an $O(\sqrt n)$ solution.
:::
:::

```quiz
- Greedy is optimal here
> Greedy works for "canonical" coin systems like 1,5,10,25 but not in general.

? Counting combinations (order doesn't matter) in Coin Change II requires…
+ Coins in the outer loop, amounts in the inner loop
- Amounts in the outer loop
- Sorting the coins descending
> Amounts outside counts ordered sequences instead.

? In House Robber, dp[i] = max(dp[i−1], dp[i−2] + a[i]). The two options mean…
+ Skip house i, or rob it (so house i−1 must be skipped)
- Rob house i or rob house i−1
- Rob both neighbours
> Take-or-skip with an adjacency constraint.
```

:::keypoints
- 1D DP: `dp[i]` from a constant number of earlier states (rolling variables give $O(1)$ space) or from all of them ($O(n^2)$).
- Take/skip (robber), last-choice (coins, squares, stairs), last-piece (word break, decodings).
- Greedy fails for general coin systems; DP is exact.
- Loop order matters: coins outside = combinations, amounts outside = ordered sequences.
- Break circular problems by fixing one decision (exclude the first or the last).
:::
