---
title: Context — Sharing Data Without Prop Drilling
level: intermediate
time: 25
summary: Pass data deep into the tree without threading props through every level. Create context, provide it with React 19's `<Context value>` syntax, read it with useContext or use(), and combine it with a reducer for app-wide state.
---

Some data is needed almost everywhere: the current user, the theme, the selected model, the language. Passing it as props through every layer ("prop drilling") is tedious and fragile. **Context** lets any component deep in the tree read it directly.

:::def Prop drilling
Passing a prop through many intermediate components that don't use it themselves, just so a deeply nested child can receive it.
:::

:::def Context
A way to make a value available to **every component below** a provider, no matter how deep. Components "subscribe" with `useContext(MyContext)` (or `use(MyContext)`) and re-render when the value changes.
:::

:::syntax
```jsx
const ThemeContext = createContext("light");          // 1. create (with a default)

<ThemeContext value="dark">                           // 2. provide (React 19 syntax)
  <Page />
</ThemeContext>

const theme = useContext(ThemeContext);               // 3. read anywhere below
```
:::

## A first context

```jsx run level=easy
import { createContext, useContext, useState } from "react";

const ModelContext = createContext("claude-opus-5-5");

function Header() { return <h3>Assistant <ModelBadge /></h3>; }      // doesn't need the prop at all
function ModelBadge() {
  const model = useContext(ModelContext);                             // reads it directly
  return <code style={{ fontSize: 13 }}>{model}</code>;
}
function Footer() {
  const model = useContext(ModelContext);
  return <p className="muted">Answers generated by {model}.</p>;
}

export default function App() {
  const [model, setModel] = useState("claude-opus-5-5");
  return (
    <ModelContext value={model}>
      <select value={model} onChange={(e) => setModel(e.target.value)}>
        <option>claude-opus-5-5</option><option>claude-sonnet-5-5</option><option>claude-haiku-4-5</option>
      </select>
      <Header />
      <Footer />
    </ModelContext>
  );
}
```

:::note React 19 syntax
In React 19 you render the context itself as the provider: `<ModelContext value={…}>`. Older code writes `<ModelContext.Provider value={…}>` — it still works, but the new form is shorter.
:::

## Theme switching with context

```jsx run level=intermediate
import { createContext, useContext, useState } from "react";

const ThemeContext = createContext(null);

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState("dark");
  const toggle = () => setTheme((t) => (t === "dark" ? "light" : "dark"));
  return <ThemeContext value={{ theme, toggle }}>{children}</ThemeContext>;
}

function useTheme() {                                   // a custom hook hides the context details
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error("useTheme must be used inside <ThemeProvider>");
  return ctx;
}

function Panel({ children }) {
  const { theme } = useTheme();
  const dark = theme === "dark";
  return (
    <div style={{ background: dark ? "#111827" : "#f8fafc", color: dark ? "#f1f5f9" : "#0f172a", padding: 16, borderRadius: 12 }}>
      {children}
    </div>
  );
}

function ToggleButton() {
  const { theme, toggle } = useTheme();
  return <button onClick={toggle}>{theme === "dark" ? "☀️ Light" : "🌙 Dark"} mode</button>;
}

export default function App() {
  return (
    <ThemeProvider>
      <Panel>
        <h3>Settings</h3>
        <p>Any component can read or change the theme — no props passed down.</p>
        <ToggleButton />
      </Panel>
    </ThemeProvider>
  );
}
```

:::tip The provider + custom hook pattern
Wrap a context in a `XProvider` component (owns the state) and a `useX()` hook (reads it and throws a helpful error if used outside the provider). This is how most real apps and libraries expose context.
:::

## Context + reducer: app-wide state

For state that many components read **and** update — like a conversation list — combine a reducer with context.

```jsx run level=advanced
import { createContext, useContext, useReducer } from "react";

const ChatsContext = createContext(null);
const DispatchContext = createContext(null);

function chatsReducer(chats, action) {
  switch (action.type) {
    case "added": return [...chats, { id: action.id, title: action.title, pinned: false }];
    case "pinned": return chats.map((c) => (c.id === action.id ? { ...c, pinned: !c.pinned } : c));
    case "deleted": return chats.filter((c) => c.id !== action.id);
    default: throw new Error(action.type);
  }
}

function ChatsProvider({ children }) {
  const [chats, dispatch] = useReducer(chatsReducer, [
    { id: 1, title: "RAG architecture", pinned: true },
    { id: 2, title: "Debug my hook", pinned: false },
  ]);
  return (
    <ChatsContext value={chats}>
      <DispatchContext value={dispatch}>{children}</DispatchContext>
    </ChatsContext>
  );
}
const useChats = () => useContext(ChatsContext);
const useChatsDispatch = () => useContext(DispatchContext);

let nextId = 3;
function NewChatButton() {
  const dispatch = useChatsDispatch();
  return <button className="primary" onClick={() => dispatch({ type: "added", id: nextId++, title: `New chat ${nextId - 1}` })}>+ New chat</button>;
}

function ChatList() {
  const chats = useChats();
  const dispatch = useChatsDispatch();
  const sorted = [...chats].sort((a, b) => Number(b.pinned) - Number(a.pinned));
  return sorted.map((c) => (
    <div key={c.id} className="card row" style={{ justifyContent: "space-between" }}>
      <span>{c.pinned && "📌 "}{c.title}</span>
      <span className="row">
        <button onClick={() => dispatch({ type: "pinned", id: c.id })}>{c.pinned ? "Unpin" : "Pin"}</button>
        <button onClick={() => dispatch({ type: "deleted", id: c.id })}>🗑</button>
      </span>
    </div>
  ));
}

function Counter() { return <p className="muted">{useChats().length} conversations</p>; }

export default function App() {
  return (
    <ChatsProvider>
      <div className="stack" style={{ maxWidth: 400 }}>
        <NewChatButton />
        <ChatList />
        <Counter />
      </div>
    </ChatsProvider>
  );
}
```

Splitting state and `dispatch` into two contexts means components that only dispatch (like `NewChatButton`) don't re-render when the list changes.

## Reading context with use()

React 19's `use()` can read a context too — and unlike hooks, it may be called **conditionally**.

```jsx run level=advanced
import { createContext, use } from "react";

const PermissionsContext = createContext({ canDelete: false });

function DeleteButton({ owner }) {
  if (!owner) return null;                         // early return…
  const { canDelete } = use(PermissionsContext);   // …then read context: allowed with use()
  return <button disabled={!canDelete}>{canDelete ? "Delete" : "Delete (no permission)"}</button>;
}

export default function App() {
  return (
    <div className="stack">
      <PermissionsContext value={{ canDelete: true }}><DeleteButton owner /></PermissionsContext>
      <PermissionsContext value={{ canDelete: false }}><DeleteButton owner /></PermissionsContext>
    </div>
  );
}
```

## When not to use context

- **Data used by one or two levels** → just pass props; it's clearer.
- **Rapidly changing values** read by many components (like a text field updated on every keystroke) → every consumer re-renders; keep that state local, or use a store with selectors (Zustand, in the Ecosystem module).
- **Server data** (lists from an API) → a data-fetching library caches and shares it better.

:::ai
Typical contexts in an AI app: the **current user and plan**, the **selected model and settings**, the **theme**, and a **conversation provider** exposing messages plus actions like `send`, `stop`, `regenerate`.
:::

```quiz
? What problem does context solve?
+ Passing data deep into the tree without threading props through every level
- Making components render faster
- Fetching data from servers
> It avoids prop drilling.

? In React 19, how do you provide a context value?
+ <MyContext value={x}>…</MyContext>
- <MyContext.Consumer value={x}>
- provideContext(MyContext, x)
> <MyContext.Provider> still works, but is no longer needed.

? What happens to components reading a context when its value changes?
+ They re-render
- Nothing until the page reloads
- Only the provider re-renders
> That's why fast-changing values in context can hurt performance.
```

:::keypoints
- `createContext(default)` → provide with `<Ctx value={…}>` → read with `useContext(Ctx)` or `use(Ctx)`.
- Wrap context in a **Provider component + custom hook** for a clean API.
- Context + `useReducer` gives app-wide state; split state and dispatch contexts.
- Don't overuse context: local state and props are simpler; stores and data libraries suit other cases.
:::
