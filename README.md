# Techbook — interactive courses

One static website that holds every course. The home page (`index.html`) lists the courses; each course opens in its own section of the site, and the **Courses** menu in every course's top bar switches between them.

## Open it

Double-click `index.html`, or serve the folder (closer to how it runs when deployed):

```bash
python3 -m http.server 8000      # then open http://localhost:8000
```

## Deploy

The whole folder is a static site with no server code. Upload it as-is to any static host (GitHub Pages, Netlify, Cloudflare Pages, Vercel, S3). The site root is this folder. Course URLs are `/<folder>/`, for example `/python/#/l/start-here`.

`_template/` is only a starting point for new courses. Leave it out of the upload, or keep it. Nothing links to it.

## Layout

```text
index.html          site home: the course catalogue
courses.js          ★ the course registry (name, colours, description) — one entry per course
stats.js            generated by build.py: lesson / project / example counts for the home page
build.py            builds every course, then regenerates stats.js
shared/
  css/style.css     the design system (light + dark) used by every page
  js/app.js         the course engine: router, renderer, search, glossary, progress, course switcher
  js/hub.js         the site home page
  vendor/           CodeMirror (all modes), marked, KaTeX
python/ typescript/ react/ threejs/ dsa-cpp/ system-design/
  index.html        course shell + its SITE config (hero, colours, storageKey)
  build.py          bundles content/ → assets/js/content.js (each course can add its own checks)
  content/          the lessons (Markdown)
  assets/js/        content.js (generated) + the course's runner (Pyodide, TS compiler, React, three.js, C++)
_template/          a blank course to copy when adding a new topic
```

Anything that belongs to one course only stays in that course's folder. Examples are the TypeScript compiler (`typescript/assets/vendor/ts/`), the DSA visualizers and styles (`dsa-cpp/assets/`), and the system-design diagrams and simulators (`system-design/assets/`).

## Build

```bash
python3 build.py                  # build every course, then refresh stats.js
python3 build.py --only=python    # build one course
python3 build.py --stats          # only refresh the home-page counts
python3 build.py -- --no-verify   # pass flags through to every course's build.py
```

Each course can still be built on its own (`cd python && python3 build.py`). Afterwards, run `python3 build.py --stats` at the root to update the counts on the home page.

## Add a new course

1. Copy `_template/` to a new folder. The folder name becomes the URL, for example `rust/`.
2. In the new `index.html`, replace each `TODO`: the name, tagline, logo text, accent colours, hero text, and a unique `storageKey`.
3. Write lessons in `content/`. Lessons use the same Markdown extensions as every other course: `:::def`, `:::tip`, quizzes, exercises, and so on (see `python/README.md`).
4. Add an entry to `courses.js` with the same `path` and `storageKey`.
5. Run `python3 build.py` at the root.

The design, navigation, search, glossary, progress tracking and course switcher come from `shared/`, so a new course looks and works like the others automatically.

To make code runnable, copy the runner you need into `assets/js/` and add its `<script>` tag. The runners are `runner-python.js`, `runner-ts.js`, `runner-react.js`, `runner-three.js`, `runner-cpp.js` and `runner-js.js` (plain JavaScript in a Web Worker, in `system-design/`). Then mark code blocks with `run`.

## Shared vs per-course state

- **Theme**: one setting for the whole site (`techcontent:theme`).
- **Progress**: stored per course under its `storageKey`. The home page reads it to show progress bars and "Continue learning". It stays in the learner's browser.

A change to `shared/` affects every course. After editing the engine or the design system, check all of them.
